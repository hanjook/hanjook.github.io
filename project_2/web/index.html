1.1 Convolutions from Scratch

Convolution implemented with four loops and two loops (numpy only, zero padding, flipped kernel), compared against scipy.signal.convolve2d. Filters: 9×9 box, Dx, Dy.

Code

Four loops
def convolution_4_loop(image, kernel):
    n_rows, n_cols = image.shape
    k_rows, k_cols = kernel.shape

    convolved_image = np.zeros((n_rows, n_cols))

    pad_r = k_rows // 2
    pad_c = k_cols // 2
    padded_image = np.zeros((n_rows + 2 * pad_r, n_cols + 2 * pad_c))
    padded_image[pad_r:pad_r + n_rows, pad_c:pad_c + n_cols] = image

    flipped_kernel = np.flip(kernel, axis=(0,1))

    for ri in range(n_rows):
        for ci in range(n_cols):
            for rk in range(k_rows):
                for ck in range(k_cols):
                    curr_cell_r = ri + rk
                    curr_cell_c = ci + ck
                    convolved_image[ri][ci] += padded_image[curr_cell_r][curr_cell_c] * flipped_kernel[rk][ck]

    return convolved_image
Two loops
def convolution_2_loop(image, kernel):
    n_rows, n_cols = image.shape
    k_rows, k_cols = kernel.shape

    convolved_image = np.zeros((n_rows, n_cols))

    pad_r = k_rows // 2
    pad_c = k_cols // 2
    padded_image = np.zeros((n_rows + 2 * pad_r, n_cols + 2 * pad_c))
    padded_image[pad_r:pad_r + n_rows, pad_c:pad_c + n_cols] = image

    flipped_kernel = np.flip(kernel, axis=(0,1))

    for ri in range(n_rows):
        for ci in range(n_cols):
            image_patch = padded_image[ri:ri + k_rows, ci:ci + k_cols]
            new_pixel = np.sum(image_patch * flipped_kernel)
            convolved_image[ri][ci] += new_pixel

    return convolved_image

Runtime comparison

  • The runtimes:
    • SciPy: 0.035s
    • 2 Loop: 1.681s
    • 4 Loop: 10.006s
  • Scipy < 2 Loop < 4 Loop (time of run)
    • It is based on how much runs on Python.
    • SciPy runs on a C loop, which is faster compared to running python.
    • 4 Loop is slower than 2 Loop, because 2 Loop uses np.sum(image_patch * flipped_kernel), which runs inside NumPy’s compiled C code, while 4 loop has 2 extra for loops that runs on pure python.

Boundary handling

  • Zero padding was implemented by adding H/W - 1 of the kernel size to each corresponding row or column size of the image.
    • For our current example, 9x9 kernel, we would want 8 rows and columns added. Hence, 4 rows each on the top and bottom side of the image and 4 columns each on the left and right (in theory this is the case, but adding 8 rows/columns per axis would be equivalent in code).
    • The size of H/W - 1 is determined from the fact that extra pixels needed in convolving at the edges start from the center of the kernel.
  • Hence, when padding is implemented, edge pixels will be convolved with some cells of the kernel having a weight of 0, leading to pixels with lower values (darker) than pixels calculated more inside the actual image.

1.2 Finite Difference Operator

Partial derivatives of the cameraman image with Dx and Dy, gradient magnitude, and binarized edge image.

Threshold comparison

Threshold choice & tradeoff

  • Thresholds of 0.1, 0.3 and 0.5 were tested.
    • 0.1: Noisy gradient magnitudes like the grass in the image showed up. As noise has low magnitudes, 0.1 was not enough to filter them out in the binarized image.
    • 0.3: Only the main edges (cameraman’s silhouette, parts of the buildings behind) survived, which is the edges that we are mainly interested in. However, much of the building edges have also been shaved off.
    • 0.5 Only the really strong gradient magnitudes survived. The camera man’s coat against the background and the camera have sharp differences in pixels, which allowed some parts of it to remain.
  • 0.3 threshold almost fully retains the cameraman, camera and it’s stand, but the building behind them have a similar pixel intensity with the sky (or background) and have mostly been filtered out. However, as the main object in the image is the cameraman, this threshold is therefore sufficient.

1.3 Derivative of Gaussian (DoG) Filter

Gaussian built with cv2.getGaussianKernel and an outer product. First: blur, then finite difference. Second: a single convolution with DoG filters.

Method A — Gaussian blur, then Dx / Dy

Threshold comparison

What differences do you see? (vs. 1.2)

  • At a reasonable threshold, the binarized edges in the gaussian smoothed image are much more smoother than the edges from the original image.
  • Reason for it is that gaussian Smoothing smooths the image’s edges by convolving them with a filter, and the pixels that were near but not a part of the edge before now have weighted pixel magnitude from an edge pixel as well. Hence the gradient magnitude is smoothed out, which gives the smoothing effect on the binarized edges.
  • On the other hand, weak edges have been blurred by it’s surrounding background and were diminished through convolutions.
  • This can be drawn from the fact that at a lower threshold, the edges are thicker and there are still weak noise (grass) in the binarized image and vice versa. Pixels that were previously not an edge but have picked up edge pixel weights through convolution have a higher magnitude towards the edge, and lowers as it moves away. Hence, when the threshold lowers, pixels further away from the edge are still picked up, resulting in 1 (white), thus thickening the edge picked up.
  • Also, the optimized smooth threshold is lower than the original (0.1 < 0.3) as the gaussian smoothing has smoothed the gradients (lower difference in pixel), hence naturally need a lower threshold to match the original one.

Method B — Single convolution with DoG filters

Threshold comparison

Verify: same result as Method A?

  • Convolution is associative, which means that applying whichever convolution first does not change the output result. It is applying a weight sum of pixels to the arrays, hence does not matter whichever is applied first.
  • This is because in method A, convolve2d(...mode='same') was used twice. mode='same' crops out the newly padded pixels resulting from the convolution, which is a loss of information for the pixels at the very edge of the image when convolving again with Dy and Dx. Hence, the very end row and column pixels of the image should differ from the DoG method, where the information is already applied to the Gaussian kernel, then to the image. Hence, the end pixels of the image was cropped away, and the rest of the internal pixels were successfully compared to be equal.

Part 2: Fun with Frequencies

2.1 Image “Sharpening”

Unsharp masking as a single convolution: (1 + α)·δ − α·G.

How unsharp masking works

  • First applying the gaussian blur allows isolation of the low frequencies in the image. This is due to sharp variations in pixels are being canceled out by blurring them, while the mild variations are less affected. Frequencies are changes in the pixels, hence, high frequencies (sharp variations) are smoothed out and the lower frequencies are retained.
  • The high frequencies are then attained by subtracting the lower frequency image resulting from a gaussian blur.
  • For unsharp masking, the theory is that edges and details of the image are within the high frequency domain. Hence, reinforcing that high frequency allows a ‘sharpening’ of the image. Adding multiple high frequency images onto the image would further sharpen it.

Taj Mahal

  • The sharpened Taj Mahal shows more emphasis on the edges of the buildings. For example, the bricks are more defined and the black line structures on the left of the Taj Mahal are more prominent than before. Overall, the building seems more defined than before.

Image of my choice — blurry Golden Gate Bridge, varying α

How does changing α change the result?

  • Introducing a higher alpha would mean that the high frequency version of the image is added in multiples. At a high alpha, this would put unnecessary emphasis on pixels that were part of the high frequency but did not need emphasis and brighten them.
  • At a moderate alpha, the image still retains the original overall intensity, but allows slight emphasis on the edges, which is an ideal ‘sharpening’ of the image. This is true in the image above at alpha=2, where the bridge is more defined than before.

Evaluation — sharp image → blur → re-sharpen

Original vs. sharpened — observations

  • The blur then resharpen method did not seem to result back into the original image.
  • This is because when blurred through gaussian, the original high frequency information is lost. The secondary high frequencies would be based on the blurred image and would be sharpen the blurred image, but not to the level of the original one.

2.2 Hybrid Images

Low-pass (Gaussian) of one image + high-pass (impulse − Gaussian) of another, after alignment.

Hanjoo × Tori — full process

Inputs

Aligned images and Fourier analysis

Alignment

  • The for facial images, they were aligned by aligning these points: The top-left of the left eye and the bottom right of the right eye in each subject image.

Cutoff frequency choice

  • Gaussian sigmas determine how wide the bell curve applied to the kernel is. With a larger sigma, the bell curve will be flatter, but would need a larger kernel. A kernel size of 6sigma + 1 was used as a dynamic kernel size, as most of the weights of the bell curve can be included by 3sigma away from the center, with the 1 added to make sure the kernel sizes were odd.
  • The sigmas were selected through trial and error based on the resulting hybrid image. The ideal result would be to see the high frequency image more close up and the low frequency image more from afar.
  • Sigma for low-pass filters were ideally high enough so that the high frequencies are filtered out and blurred, but not too much so that the features that determine the shape of the figures are not unrecognizable from afar. On the other hand, high-pass filters ideally leave only high frequency and some of the mid-level frequency features left to be recognizable up close. So the sigma is not too low, as subtracting a slightly blurred image will leave only the highest frequencies behind and not the medium frequencies.
  • The cutoff frequencies were found by adjusting the sigma values experimentally and evaluated by being near and far visually.

2.2 Color in Hybrid Images Bells & Whistles

Does color work better in the high-frequency component, the low-frequency component, or both?

  • Color in low frequency allows more dominance in that frequency over a gray low frequency and is more apparent than before.
  • The color in the high frequency does not contrast as strongly in comparison to gray high frequency images. The colors are not that apparent.
  • Hence, colors in both seem almost equivalent to the image when there are colors in the low frequency only.

Conclusion

  • It could be said that the best color combination is when the lower frequency image is of color and the higher frequency image is gray. Colors are normally in low frequencies and are lost in high frequencies. Hence, the best differentiation between the low and high frequencies come up when the low frequency image is reinforced with color.

2.3 Gaussian and Laplacian Stacks

Stacks (no downsampling) applied to the apple and orange, recreating Figure 3.42 (a)–(l) from Szeliski.

Implementation

  • Gaussian Stack:
    • This was simple without downsampling, it was re-applying gaussian blurs to the resulting blur, for a set amount of levels.
    • The sigmas were added by 4 at each level, to ensure each level had an obvious difference for calculating the laplacians.
  • Laplacian Stack:
    • The Laplacian stacks were computed by using the differences of the gaussian blurs between each level. The lowest level in the Laplacian stack used the single blur in the lowest level of the Gaussian Stack.
    • This effectively stores the information lost when applying the gaussian blurs.
  • Hence, the full summation of the laplacian stack would end up in the original image.
  • Each image is at level 0, 2, 4 is a laplacian level of the image. They show the information lost after each gaussian blur. These are the information lost at each level:
    • 0: We can see the high frequencies of the image: the hard edges of the apple, textures of the orange
    • 2: We can see the softer edges of the images, the overall shape of the fruits
    • 4: We can see some colors that made up the fruits
  • Also, the images in the figure were clipped to get a better visual of the images, as laplacians have values around 0. (It was also to somewhat match the figure in the paper as well)

2.4 Multiresolution Blending

Blending with Laplacian stacks of each image and a Gaussian stack of the mask.

The Oraple

  • The blending mask was constructed by creating an zeros array equally sized to the images and filling the area of interest with 1. In terms of left, the left half of the array was filled with 1s and for right, the right half was filled with 1s
  • Then, they were gaussian blurred with the same amount of levels of images. These blurred. masks were then applied to the apple/oranges at each corresponding level by multiplying itself to the images and smoothing them out. The smoothing factor at the lowest level would be the highest.
  • This is natural as high levels of the laplacian retain the high frequency features which should not be smoothed out, while the low frequencies in the lower levels (such as color) are smoothed out, mixing the two objects at the seam.
  • Since the orange and apple in the image are somewhat of similar color, the blurring and mix of pixel weights were did not have a relatively high difference, hence a somewhat smooth transition in color was achieved. However, the texture difference is still apparent.
