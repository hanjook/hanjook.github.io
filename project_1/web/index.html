Single-Scale Alignment (Low-Resolution JPEGs)

Results of the naive, single-scale exhaustive search on cathedral.jpg, monastery.jpg, and tobolsk.jpg, using NCC as the matching metric.

Scoring NCC

  1. Flattens two patches (1D vector) from each channel
  2. Subtracts mean for each patch, removing the brightness offset between the two
  3. Compute normalized cross-correlation by dividing their dot product by the product of their L2 norms:
    1. Dot product: np.sum(a*b)
    2. Norm product: np.linalg.norm(a) * np.linalg.norm(b)
    3. The resulting score lies between [-1,1], with larger values indicating stronger similarity

Align

  1. Takes one fixed channel and a channel to shift.
    1. (conditional - only on multi-scale) The image is 'np.roll'ed by the [dy,dx] taken from the previous level's search in shift
  2. A fixed cropped location is extracted from both the shifted channel and the reference channel for scoring
    1. Margin is 10% of the image, with the search_radius as the minimum.
  3. The NCC is calculated between the two crops while shifting
    1. Exhaustively tries all shifts in search_radius [dy,dx] and calculates the NCC
  4. The [dy,dx] with the highest score is selected as the best shift match
Comments:
  • The cropping
    • It is scored after cropping so that the border that is not part of the actual image does not corrupt the scoring
    • After looking at the data, a 10% of the image on each side seemed an appropriate size to crop out, as it retains most information of the image while clearing the borders
    • The magnitude of the search radius is set as the minimum crop margin, it is a safeguard against the roll, but it is expected at most times that the 10% will be taken
  • Multi-scale consideration
    • The initial [0,0] alignment should be translated using the optimal shift found in the previous pyramid level

Multi-Scale Pyramid Alignment (All 14 Provided Images)

Coarse-to-fine pyramid results (NCC, computed on raw RGB pixel values) for every provided glass plate scan.

Downscale and Align

  1. Builds an image pyramid for all three channels by repeated downsampling at scale=0.5 with anti-aliasing.
  2. Pyramid depth is decided relative to the resolution of the image
    1. halves the image size until it drops below 200px on its shorter side (h/w)
  3. Searches coarse-to-finest, doubling the running [dy,dx] every return to its scale above and halving the search_radius at each step down.
  4. Results in a local optimum [dy,dx] shift in each of B and R to match against green
Comments
  • An adaptive pyramid depth was used because it was noticed that at a relatively high fixed depth, the doubling of the [dy,dx] had an immense effect on the results of smaller images (jpgs)
  • The experiment initially started with Blue as the fixed reference, but the resulting image was similar to the incorrect emir example on the Project 1 deliverables
    • Changing the fixed reference to Green showed better results by through visual inspection
  • Initially, the search radius after the first one was fixed at a small number (e.g. 20px → 3px → 3px), but it seemed to strict on images that had deep pyramid levels as they get stuck on a wrong shift. Hence a looser 'halving search radius' method was taken that resulted in better performance (e.g. 20px → 10px → 5px).

Automatic Cropping

Sequential / Hybrid Method
Used the Sobel gradient-energy detection to search for edges of the actual image and searched inwards from the edge of the whole image.
Along with Sobel, searched for dark rows from the edge of the whole image to target the black borders.

  1. find_black_border / auto_crop_black:
    1. Using a grayscale of the image.
    2. Separately scans for a run of mostly-dark rows/ columns near each edge, getting rid of the plate's black borders
  2. detect_borders / auto_crop:
    1. (For each channel) Computed Sobel gradient-energy per row/column
    2. It finds the local maximum in a bandwidth of 10% of the image, which would indicate an edge (ideally of the real image)
    3. Compiles the edges found from each channel and takes the intersection box for the final crop
  3. Both are applied in that order to get the final crop

Comments
  • Glass plate crops:
    • The search band was restricted to 10%, which was a restraint attempting to prevent over-cropping into plain background of the actual image (e.g. skies)
    • The colored letters in the black borders that triggered the spike-detection and would prevent cropping from proceeding into the image content. Hence, built another detector that explicitly crops out the black borders
    • Since the algorithm was applied to all channels and compiled using the intersection, I could effectively cut out the meaningless color plate edges and extract the meaningfully part of the image that stacks.
  • Black border cropping:
    • This algorithm tries to detect a continuous strip of black starting from the edge of the whole image. For rows/columns that have a darkness level that persists for a minimum run, I trust it to be a black border.
    • Avoid setting the threshold to make it too dark, as the numbers make the strip less darker, hence would not be considered black at a low threshold
    • It is robust against bursts of bright strips as there is a minimum run threshold. However, once it finds that it is a border (surpasses minimum run), then the next row/column that isn't dark will be considered the other end of the black border.
    • However it may be weak against the bursts of bright strips after a black border has been determined.

Automatic White Balance

  1. Computes each channel's mean, and the overall gray mean across all three
  2. Scales each channel so its mean matches that overall gray mean

emir

cathedral

Comments:
  • This is based on the gray-world assumption: where in a real scene, colors should average out almost to neutral, so a channel whose average is off the gray mean is read as evidence of a color cast and corrected back toward the others.
  • This has to run after cropping, because color borders that are not part of the actual image may skew the means of each channel.

Automatic Contrasting

  1. Used PIL.ImageOps.autocontrast with cutoff =2, which ignores the most extreme 2% of pixels on each end before stretching the remaining range to fill [0,255]

  • Hence, this method also has to run after cropping.
  • However, the higher contrast in the image overly highlighted some tones in the image.

Better Color Mapping

Used my religious painting's result against the ground truth result on LOC to calculate a color mapping matrix.
This matrix was then used to map the emir example to the estimated real RGB

The bells and whistles are applied sequentially: Automatic Cropping → Automatic White Balance → Automatic Contrasting → Better Color Mapping.

  1. Loaded my own aligned religious_painting result, and the Library of Congress's official professionally-restored version of the same photo, as a color reference
  2. Manually labelled bboxes of different color patches in the image using ply.ginput()
    1. blue robe, gold robe, green robe, white robe, red robe, door, wall
  3. Converted each bbox into a cropped region, and averaged pixels in each region to get one representative color per patch, per image
  4. Solved for a 3x3 matrix that best maps my patch colors onto the reference's patch colors, using least-squares - np.linalg.lstsq()
  5. Applied that matrix to a different image (emir), to test the results

emir

cathedral

Comments:
  • There's no reason to assume the RGB filters in Prokudin-Gorskii actually used in the 1900s line up exactly with a modern display's RGB. A 3x3 matrix lets each output channel be a blend of all three input channels, which can correct for that cross-channel mismatch in a way a per-channel-only correction (such as white balancing) cannot
  • In order to calculate this matrix, I needed a real ground truth image to use against my own image. The religious_painting was chosen to calculate this matrix as there were simple, almost definite colors that could be used for mapping
  • The results showed that the color mapping had succeeded, but the tone of the image became very warm overall. This is suspected to be a cause of the label areas from each image to not be equal as each image was labeled separately, hence the mapped pixels were not exactly the same location
  • A solution to this would be to make the location of the bboxes identical, perhaps translating the bboxes from one image mathematically to the other.
